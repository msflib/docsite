    MSF Laravel Monorepo¶

    This repository is the monorepo for the MSF Laravel package ecosystem. It groups reusable library packages for core utilities, auth, users, GraphQL, and other business domains into a single workspace that can be installed and validated as a coherent platform.

    What is in this repo¶

    The monorepo includes packages such as:

    • msflib/core for shared kernel primitives and utilities
    • msflib/auth for authentication and authorization features
    • msflib/user for user-specific domain logic and scaffolding
    • msflib/graphql for GraphQL integration and Lighthouse setup
    • msflib/config, msflib/common, msflib/inventory, msflib/sales, msflib/notify, and related packages for domain-specific functionality
    • testsite as a consumer app used to validate package installation via the private registry

    Prerequisites¶

    • PHP 8.2+
    • Composer
    • Laravel-compatible local environment
    • Optional: access to the private registry or Satis bucket for downstream install tests

    Bootstrapping the monorepo¶

    From the repo root:

    cd laravel
composer install

    For package-level validation:

    for file in packages/*/composer.json; do
  composer validate --working-dir="$(dirname "$file")" --no-check-publish --no-check-lock
done

    Monorepo validation¶

    The project provides monorepo validation tooling:

    composer monorepo:validate

    This is the main way to validate the workspace structure and package relationships before a release or change is merged.

    Composer package pattern¶

    The root repository config declares path repositories for all packages under packages/*. This allows local package development without publishing every package to Packagist or a private registry first.

    "repositories": [
  {
    "type": "path",
    "url": "packages/*",
    "options": {
      "symlink": true
    }
  }
]

    This pattern is how local monorepo work is wired together before pushing to a branch or release channel.

    Consumer app installation model¶

    This monorepo is designed to be consumed from downstream Laravel apps via Composer artifacts and a private registry mirror, not only through direct path repositories.

    {
  "repositories": [
    {
      "type": "artifact",
      "url": ".msflib-registry/dist"
    }
  ],
  "require": {
    "msflib/user": "dev-dev"
  }
}

    A downstream app mirrors the registry channel and then installs the package normally. This is the pattern documented in the project README and used by testsite.

    Package map¶

    • Core — foundational utilities and framework-agnostic primitives
    • Auth — authentication service provider and permissions integration
    • User — user domain and user service package
    • GraphQL — Lighthouse and GraphQL package layer
    • Registry — Satis, artifact mirroring, and release channels
    • Summary — docs index

    Important operational notes¶

    • package releases are managed through the monorepo and private registry workflow
    • packages are released as versioned artifacts and then mirrored into downstream app installs
    • the root workspace uses service providers from package providers to register Laravel features at runtime

    Typical local usage¶

    composer install
php artisan test

    The exact commands depend on the package or app under test, but the monorepo workflow is intentionally organized around package-level validation and downstream consumer verification.
