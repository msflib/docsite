    MSF Laravel Common¶

    msflib/common is the shared foundation package for the wider MSF Laravel ecosystem. It provides reusable common models, GraphQL schema fragments, provider registration, and migration support so downstream packages can build on a consistent base rather than duplicating the same patterns across the stack.

    Package purpose¶

    This package is designed to provide the common structural layer for Laravel applications built with MSF components.

    It is responsible for:

    • service-provider registration in Laravel
    • shared GraphQL types and reusable schema fragments
    • model conventions for common domain entities
    • database migration support for shared catalog data

    Key integration points¶

    The package registers its GraphQL schema by listening to Lighthouse schema build events and stitching the package-level schema into the app schema.

    Event::listen(BuildSchemaString::class, function ($schemaString) use ($graphql) {
    return (new SchemaStitcher($graphql))->getSchemaString();
});

    This pattern keeps the common schema modular while allowing the application to assemble a single composite GraphQL schema at runtime.

    Composer installation¶

    composer require msflib/common

    The package declares msflib/graphql as a dependency, so it assumes the downstream app is already configured for Lighthouse-based GraphQL work.

    Package types and model conventions¶

    The included GraphQL schema defines reusable content types such as:

    • Category
    • Status

    These are common reference entities that can be extended or consumed by higher-level business packages.

    Development workflow¶

    Local package validation is handled through the package-level Laravel Testbench setup:

    composer install
composer test

    The package also exposes lint and formatting tools such as:

    composer format
composer lint

    Operational notes¶

    • keep the package generic and reusable
    • avoid domain-specific logic that belongs in specific business packages
    • prefer schema stitching and service-provider registration over custom bootstrapping logic in app code
    • keep shared database and model conventions consistent with other MSF packages
