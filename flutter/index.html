    khflutterlib¶

    khflutterlib is the shared Flutter foundation for product teams building company apps from a consistent set of core primitives, design tokens, reusable UI, and screen patterns. It is a monorepo of independently versioned packages that are consumed by applications through git-based dependencies rather than a single published package.

    What this monorepo includes¶

    • kh_core for shared constants, result/failure types, config, and base domain patterns
    • kh_theme for design tokens and assembled Material theme data
    • kh_ui for reusable widgets such as buttons, fields, cards, dialogs, and states
    • kh_screens for composed screen-level patterns built on the lower-level packages
    • packages/example as a runnable component gallery for visual QA and integration checks

    Prerequisites¶

    • Flutter 3.44.1 stable
    • Dart >= 3.9.0 < 4.0.0
    • Melos 7+

    Install Melos:

    dart pub global activate melos

    Quickstart¶

    From the repo root:

    cd flutter
melos bootstrap

    This installs dependencies for every package in the workspace and prepares the monorepo for local development.

    Run the example gallery:

    cd packages/example
flutter run

    Run checks across packages:

    melos run analyze
melos run test
melos run test:flutter

    Package guidance¶

    Use the package that matches the layer you need in your app:

    • kh_core for common primitives and domain contracts
    • kh_theme for theme and design-system setup
    • kh_ui for reusable widgets and shared form patterns
    • kh_screens for full-screen flows such as splash or onboarding screens

    Consumer app dependency pattern¶

    Apps consume the monorepo via git dependencies, not pub.dev:

    dependencies:
  flutter:
    sdk: flutter
  kh_core:
    git:
      url: https://github.com/msflib/flutter.git
      path: packages/kh_core
      ref: kh_core-v0.1.1
  kh_theme:
    git:
      url: https://github.com/msflib/flutter.git
      path: packages/kh_theme
      ref: kh_theme-v0.1.1
  kh_ui:
    git:
      url: https://github.com/msflib/flutter.git
      path: packages/kh_ui
      ref: kh_ui-v0.1.1+1

    This is the intended integration model for a separate application, and it matches the repo's current architecture and release flow.

    Typical app setup¶

    import 'package:flutter/material.dart';
import 'package:kh_theme/kh_theme.dart';
import 'package:kh_ui/kh_ui.dart';

void main() => runApp(const MyApp());

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      theme: KhTheme.light(),
      darkTheme: KhTheme.dark(),
      home: Scaffold(
        body: Center(
          child: KhButton.primary(
            onPressed: () {},
            child: const Text('Continue'),
          ),
        ),
      ),
    );
  }
}

    Notes and expectations¶

    • kh_core stays intentionally free of Flutter dependencies where possible.
    • kh_theme is the visual baseline for every package in the library.
    • kh_ui wraps standard Material widgets and keeps the app-level customization model straightforward.
    • kh_screens is intended to provide higher-level product flows built on the reusable primitives below it.

    This repo is most useful when consumed as a coordinated library family rather than as a single app, and these docs are organized to make that consumer pattern obvious.
