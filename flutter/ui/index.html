    UI¶

    The kh_ui package provides the reusable UI toolkit for the monorepo. It wraps common Material widgets and keeps the app-level customization model consistent with the design system created by kh_theme.

    Package purpose¶

    kh_ui includes high-value widgets for common product interfaces:

    • KhButton for consistent buttons and icon buttons
    • KhTextField for themed form inputs
    • KhCard for content containers
    • KhDialog for alerts and confirmations
    • KhLoadingState, KhEmptyState, and KhErrorState for screen states
    • KhChip and KhBadge for status-style indicators

    Status¶

    The package is active and used as the building block layer for product UI.

    Installation¶

    dependencies:
  kh_ui:
    git:
      url: https://github.com/msflib/flutter.git
      path: packages/kh_ui

    Button usage¶

    import 'package:kh_ui/kh_ui.dart';

KhButton.primary(
  onPressed: () {},
  child: const Text('Continue'),
);

KhButton.outline(
  onPressed: () {},
  child: const Text('Cancel'),
);

    These constructors follow the app's configured theme rather than hard-coded colors or dimensions.

    Text field usage¶

    KhTextField(
  decoration: const InputDecoration(labelText: 'Email'),
  keyboardType: TextInputType.emailAddress,
  validator: (value) => value == null || value.isEmpty ? 'Required' : null,
);

    kh_ui values theme defaults while still allowing a single input to override a specific decoration detail.

    Card and dialog usage¶

    KhCard(
  child: Padding(
    padding: const EdgeInsets.all(16),
    child: Text('Card content'),
  ),
);

KhDialog.alert(
  context: context,
  title: 'Ready',
  content: 'Your changes are saved.',
);

    Screen-state components¶

    KhErrorState(
  failure: KhValidationFailure('Something went wrong'),
  onRetry: () {},
);

    These states are intended to keep user feedback consistent across screens without requiring each screen to reinvent the same UI patterns.

    Theming principle¶

    Every widget in kh_ui should prefer Theme.of(context) over direct token reads. This keeps the package flexible for consuming apps that customize the brand color or font family using KhTheme.
