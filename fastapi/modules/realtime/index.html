    msflib.realtime¶

    Purpose¶

    msflib.realtime pushes backend events to connected clients over Server-Sent Events (SSE) or WebSocket on named channels, with ordered, resumable delivery and short-lived ticket authentication for browser clients. It is the canonical replacement for per-app SSE code in msflib host apps.

    It handles ordering, replay and cross-worker broadcast. It does not handle client-sent domain messages such as typing indicators.

    Install¶

    msflib.realtime ships inside the msflib core package and is always available once core is installed. For WebSocket support the ASGI server needs a WebSocket adapter:

    [tool.poetry.dependencies]
msflib = { git = "https://github.com/msflib/fastapi.git", subdirectory = "core", rev = "core-v0.3.0" }
uvicorn = { extras = ["standard"], version = "^0.30" }   # brings websockets

    uvicorn[standard] installs the websockets library that Starlette's WebSocket support depends on. The module also requires redis when the Redis Streams backend is used, but it is already a declared dependency of msflib core.

    Wiring into a host app¶

    Three steps: build a hub, mount the router, and call hub.emit(...) wherever you need to push an event.

    1 — Add RealtimeSettings and build the hub¶

    # app/core/config.py
from msflib.realtime.config import RealtimeSettings

class AppSettings(RealtimeSettings, CoreSettings, SettingsBase):
    pass

settings = AppSettings()

    # app/core/realtime.py
from app.core.config import settings
from msflib.realtime.config import RealtimeSettings, build_hub

hub = build_hub(settings.scope("REALTIME").unwrap())

    build_hub uses the Redis Streams backend when REALTIME_REDIS_HOST and REALTIME_REDIS_PORT are set, and the in-process memory backend otherwise. The memory backend is fine for development and single-worker deploys.

    2 — Mount the router¶

    from app.core.realtime import hub
from msflib.realtime import (
    TicketSigner,
    bearer_authenticator,
    route_authorizers,
)
from msflib.realtime.config import RealtimeSettings
from msflib.realtime.router import router as realtime_router

_rt = settings.scope("REALTIME").unwrap()
_signer = TicketSigner(secret=settings.scope("CORE").SECRET_KEY, ttl_seconds=_rt.ticket_ttl_seconds)

app.include_router(
    realtime_router(
        hub=hub,
        authenticators=[
            bearer_authenticator(resolve_token),   # see §Authentication below
        ],
        authorizer=route_authorizers({"workspace:": workspace_authorizer}),
        signer=_signer,   # enables POST /tickets; also adds ticket auth to stream endpoints
        settings=_rt,
    ),
    prefix="/api/v1/realtime",
    tags=["realtime"],
)

    Routes added:

    Method Path Effect
    GET /stream SSE stream for one channel; ?channel=workspace:7, optional ?last_event_id=<n>
    GET /ws WebSocket connection; subscribe to many channels after connecting
    POST /tickets Issue a short-lived ticket granting named channels; requires authentication

    3 — Emit events¶

    from app.core.realtime import hub

hub.emit("workspace:7", "report-ready", {"report_id": 3})

    emit is synchronous, thread-safe, and never raises. It can be called from any service, action, background task or Celery worker.

    Authentication¶

    Browsers cannot send Authorization headers on EventSource or bare WebSockets. The recommended flow is: use a short-lived ticket for browser clients and a bearer header for server-to-server clients.

    from jose import JWTError, jwt
from pydantic import ValidationError

from msflib.realtime import StreamIdentity
from msflib.schemas.token import TokenPayload   # or your app's token schema

def resolve_token(token: str) -> StreamIdentity | None:
    """Map a bearer token to a StreamIdentity, or return None to reject it."""
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        return StreamIdentity(id=TokenPayload(**payload).sub)
    except (JWTError, ValidationError):
        return None

    A browser client fetches a ticket first, then opens the stream with ?ticket=<ticket>:

    // 1. Fetch a ticket (requires Authorization header, or a logged-in session cookie)
const { ticket } = await fetch("/api/v1/realtime/tickets", {
    method: "POST",
    headers: { Authorization: `Bearer ${accessToken}` },
    body: JSON.stringify({ channels: ["workspace:7"] }),
}).then(r => r.json());

// 2. Open the stream using the ticket (no Authorization header needed)
const es = new EventSource(`/api/v1/realtime/stream?channel=workspace:7&ticket=${ticket}`);
es.addEventListener("report-ready", e => console.log(JSON.parse(e.data)));

    Tickets are stateless, signed, grant exactly the channels they name, and expire (default 60 s). Authorization is evaluated when the stream or subscription starts, not while it is open.

    Authorization¶

    authorizer decides who may read a channel. Use route_authorizers to dispatch by channel prefix:

    from msflib.realtime import StreamIdentity, route_authorizers

async def workspace_authorizer(principal: StreamIdentity, channel: str) -> bool:
    workspace_id = channel.removeprefix("workspace:")
    return await user_may_access_workspace(principal.id, workspace_id)

authorizer = route_authorizers({
    "workspace:": workspace_authorizer,
    "conversation:": conversation_authorizer(...),
})

    The longest matching prefix wins. A channel no route claims is denied.

    Configuration¶

    Settings live in the REALTIME namespace.

    Key Flat alias Default Notes
    redis_host REALTIME_REDIS_HOST None Redis hostname; memory backend used when unset
    redis_port REALTIME_REDIS_PORT None Redis port
    redis_password REALTIME_REDIS_PASSWORD None Redis AUTH password
    history_size REALTIME_HISTORY_SIZE 1000 Events kept per channel for replay
    key_prefix REALTIME_KEY_PREFIX "realtime:" Redis key prefix
    retry_ms REALTIME_RETRY_MS 3000 SSE retry hint (ms) sent to browsers
    ping_seconds REALTIME_PING_SECONDS 15 SSE keep-alive comment interval
    ticket_ttl_seconds REALTIME_TICKET_TTL_SECONDS 60 Ticket lifetime
    max_subscriptions REALTIME_MAX_SUBSCRIPTIONS 20 Channels per WebSocket connection

    Key concepts¶

    Channel. A named string such as "workspace:7" or "conversation:conv_01...". Any string matching [a-zA-Z0-9._:/-]+ is valid. Events are scoped to a channel; a client subscribes to one or more channels.

    RealtimeHub. The central object. hub.emit(channel, event, data) pushes an event; hub.stream(channel, last_event_id) is the async generator that SSE and WebSocket transports consume. A hub wraps one backend.

    MemoryBackend. In-process storage. Events emitted by one worker are not visible to clients connected to another worker. Use this for development, tests, and single-worker deploys.

    RedisBackend. Uses Redis Streams. Every worker shares the same stream, so clients served by any worker receive every event. Requires Redis ≥ 5.0 (XADD). The event history is bounded (history_size) and approximated with XADD ... MAXLEN ~.

    Ordered delivery and replay. Each channel has an increasing integer id (1, 2, 3, ...). A reconnecting client sends Last-Event-ID (or ?last_event_id=) and receives exactly the events it missed. If the gap exceeds the retained history, a resync event is sent instead so the client knows to reload its state.

    Slow clients. A client that cannot keep up is cut off and reconnects; it then replays the backlog from its last id. No events are dropped.

    StreamIdentity. The authenticated party behind a stream: id (the account's stringified primary key or email), optional channels (set by a ticket, meaning no authorizer call is needed) and optional claims.

    Tickets. POST /tickets accepts {"channels": ["workspace:7"]} and returns {"ticket": "..."}. The ticket is a signed JWT, valid for the named channels only, expiring after ticket_ttl_seconds. TicketSigner issues and verifies tickets; pass the same signer to realtime_router.

    Integration: conversation events¶

    msflib.conversation ships a realtime bridge in msflib.conversation.integrations.realtime. It forwards every conversation domain event to the channel conversation:<public_id> after the database transaction commits, carrying ids only (never message text).

    from sqlmodel import Session

from msflib.conversation.integrations.realtime import (
    CHANNEL_PREFIX,
    ConversationRealtimeBridge,
    conversation_authorizer,
)
from msflib.realtime import route_authorizers

# In your app lifespan — pass the app's eventbus emitter:
detach = ConversationRealtimeBridge(hub).attach(get_app_emitter(app))

# Add a conversation authorizer to the route_authorizers map:
authorizer = route_authorizers({
    CHANNEL_PREFIX: conversation_authorizer(
        session_factory=lambda: Session(engine),
    ),
})

    conversation_authorizer resolves whether the principal may read the conversation using the same access rules as the HTTP surface.

    Readiness checks¶

    The module ships two readiness checks discovered automatically by Suite.from_settings when your settings compose RealtimeSettings:

    Check id Group Meaning
    realtime.redis.reachable realtime WARN when no Redis is configured (memory-only mode); FAIL when configured but unreachable
    realtime.redis.streams realtime XADD probe to verify Redis ≥ 5.0; BLOCKED when realtime.redis.reachable failed; SKIP when Redis is not configured

    See Readiness checks for how to run and extend them.

    Troubleshooting¶

    • Realtime redis_host/redis_port are not set (WARNING on startup). Normal for development; the memory backend is active and clients served by a second worker will not receive events. Set REALTIME_REDIS_HOST and REALTIME_REDIS_PORT in production.
    • SSE stream closes immediately with 401. The Authorization header is missing or unrecognised. Browser EventSource cannot send headers; use a ticket: call POST /tickets first and open the stream with ?ticket=<ticket>.
    • SSE stream closes with 403. Authentication succeeded but the authorizer denied the channel. Check the authorizer passed to realtime_router and the channel name the client is requesting.
    • WebSocket closes with code 4401. The connection was unauthenticated. The WebSocket handshake does not carry a bearer header for browser clients; use a ticket passed as ?ticket= in the URL.
    • Events received by only some clients. You are using the memory backend with multiple workers. Configure REALTIME_REDIS_HOST and REALTIME_REDIS_PORT to use the Redis backend.
    • Client receives resync event. The client was disconnected long enough that its Last-Event-ID is older than the retained history (REALTIME_HISTORY_SIZE events). The client should reload its state and resume from the new id the server provides.
    • WebSocket not supported by the server. uvicorn is missing the websockets dependency. Install uvicorn[standard] or add websockets directly.
