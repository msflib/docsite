    msflib-learning (structure)¶

    msflib-learning is the structural backbone of the FLAME engine: a configurable typed-node tree (Tree A) for academic hierarchies. Node types and hierarchy templates are data — a university names its nodes Faculty → Department → Programme → Cohort; a bootcamp names them Track → Module → Week. Neither vocabulary is baked into a column.

    Status¶

    Phase 0 skeleton. Models, actions, events and settings. Services, router, built-in templates and the module's own test suite land in Phase 1.

    Install¶

    [tool.poetry.dependencies]
msflib = { git = "https://github.com/msflib/fastapi.git", subdirectory = "core", rev = "core-v0.2.3" }
msflib-tenancy = { git = "https://github.com/msflib/fastapi.git", subdirectory = "modules/tenancy", rev = "tenancy-v0.2.1" }
msflib-learning = { git = "https://github.com/msflib/fastapi.git", subdirectory = "modules/learning", rev = "..." }

    Dependencies: msflib core · msflib-tenancy · python-ulid.

    Key concepts¶

    Node type. LearningNodeType defines a kind of structure node for a tenant: its display label, allowed child types (allowed_child_keys), and whether nodes of this kind can be enrolled in or have start/end dates. Types are per-tenant and may be tied to a template.

    Template. LearningStructureTemplate is a named preset (spec JSON) that records a canonical hierarchy shape (TemplateService.apply in Phase 1 stamps it out). Five built-in templates ship in Phase 1: university, secondary_school, bootcamp, marketplace, corporate.

    Structure node. LearningStructureNode is a node in the tree. It carries a public_id (prefixed ULID in Phase 1; caller-supplied string in Phase 0), a node type, status, visibility and optional date bounds. ClosureMixin adds parent_id and position; LearningStructureClosure stores every ancestor–descendant pair so tree queries never recurse.

    Membership. LearningNodeMembership records participation (learner, instructor, coordinator, …) on a node. Memberships have a status lifecycle (pending → active → suspended / left) and a source (manual, template, workspace, rule).

    Events. Ten domain events cover node and membership lifecycles (see eventbus/events.py). Each carries scope fields so listeners can act without re-querying.

    Layout¶

    msflib/learning/
  __init__.py
  structure/
    __init__.py
    config.py           LearningStructureSettings (namespace "LEARNING_STRUCTURE")
    models/
      node.py           all tables, schemas and enums
    actions.py          NodeTypeAction, TemplateAction, NodeAction, MembershipAction
    eventbus/
      events.py         LearningStructureEvent + EVENT_CONTRACTS

    NodeAction extends core/msflib/tree/TreeAction, which keeps the closure table in sync on every create_child, move and reorder call and works on SQLite. parent_id and position are set only through those methods, so the create and update schemas do not declare them. See core docs for the tree utilities.

    Configuration¶

    Settings in the LEARNING_STRUCTURE namespace (nested: LEARNING_STRUCTURE__*; flat aliases: LEARNING_STRUCTURE_* or bare GRAPH_BACKEND / MAX_DEPTH_HARD etc.):

    Key Default Notes
    GRAPH_BACKEND none none or age; AGE projection lands in Phase 6
    GRAPH_NAME msflib_learning AGE graph name when GRAPH_BACKEND=age
    DEFAULT_TEMPLATE None Template key applied when none is specified
    MAX_DEPTH_HARD 12 Hard cap on tree depth (enforced by services in Phase 1)
