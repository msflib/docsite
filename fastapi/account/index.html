    MSFLib Account Module¶

    The Account module provides account and profile domain APIs for MSFLib-based applications.

    Overview¶

    This module handles user account management including registration, authentication, profile management, and administrative account operations.

    Features¶

    • Account self endpoints (/account) for authenticated users
    • Optional open registration endpoint with configurable path (POST /account/open by default)
    • Admin account management endpoints (/admin/accounts)
    • Profile endpoints (/profiles) including avatar upload
    • Optional nested profile creation during account registration
    • Action classes for account and profile business logic

    Installation¶

    For Pydantic v2 (recommended):¶

    [tool.poetry.dependencies]
msflib = { git = "https://github.com/msflib/fastapi.git", subdirectory = "core", rev = "dev" }
msflib-account = { git = "https://github.com/msflib/fastapi.git", subdirectory = "modules/account", rev = "dev" }

    For Pydantic v1 (legacy):¶

    [tool.poetry.dependencies]
pydantic = "^1.10"
pydantic-settings = "^1.10"

msflib = { git = "https://github.com/msflib/fastapi.git", subdirectory = "core", rev = "core-v0.1.1" }
msflib-account = { git = "https://github.com/msflib/fastapi.git", subdirectory = "modules/account", rev = "account-v0.1.0" }

    See Pydantic Version Compatibility for migration guidance.

    Quick Start¶

    from fastapi import FastAPI
from msflib.account.router import account_router, account_admin_router, profile_router

app = FastAPI()

app.include_router(
    account_router(
        get_session=get_session,
        get_current_account=get_current_account,
        settings=settings,
        account_type=Account,
        profile_type=Profile,
    )
)

app.include_router(
    account_admin_router(
        get_session=get_session,
        role_check=role_check,
        settings=settings,
        account_type=Account,
        profile_type=Profile,
    )
)

app.include_router(
    profile_router(
        get_session=get_session,
        get_current_account=get_current_account,
        get_current_active_account=get_current_active_account,
        settings=settings,
        account_type=Account,
        profile_type=Profile,
    )
)

    If ACCOUNT.USERS_OPEN_REGISTRATION is enabled, the account router exposes exactly one open signup route. By default that route is /account/open, but you can override it with either open_registration_path= when building the router or ACCOUNT.OPEN_REGISTRATION_PATH in settings.

    API Surface¶

    Account (/account)¶

    • GET /me - current authenticated account
    • POST /open - open registration on a single configurable route (when enabled)
    • PUT /me - update current account
    • POST /verify-availability - check email/username/phone availability

    Admin Accounts (/admin/accounts)¶

    • GET / - list accounts (admin)
    • POST / - create account (admin)
    • PUT /{account_id} - update account (admin)
    • GET /{account_id} - read account (admin)

    Profiles (/profiles)¶

    • GET / - current account profile
    • GET /{account_id} - account profile by account id
    • POST / - create or update current profile
    • PUT / - update current profile
    • PUT /avatar - upload current profile avatar
    • PUT /{id} - update profile by profile id

    Key Components¶

    Actions¶

    • AccountAction - Handles account CRUD operations and business logic
    • ProfileAction - Handles profile CRUD operations and business logic

    Models¶

    • AccountBase - Base account model
    • AccountCreate - Schema for account creation
    • AccountUpdate - Schema for account updates
    • AccountRead - Schema for account responses
    • ProfileBase - Base profile model
    • ProfileCreate - Schema for profile creation
    • ProfileUpdate - Schema for profile updates
    • ProfileRead - Schema for profile responses

    Configuration¶

    Account-specific settings are accessed via settings.scope("ACCOUNT") and include: - USERS_OPEN_REGISTRATION - Enable/disable open registration - OPEN_REGISTRATION_PATH - Custom path for open registration endpoint - Other account-related configuration options

    Usage Examples¶

    Creating an Account (Open Registration)¶

    When open registration is enabled, users can create accounts without authentication:

    POST /account/open
{
    "email": "user@example.com",
    "username": "username",
    "password": "securepassword"
}

    Getting Current Account¶

    Authenticated users can retrieve their own account information:

    GET /account/me
Authorization: Bearer <token>

    Updating Account¶

    Users can update their own account information:

    PUT /account/me
Authorization: Bearer <token>
{
    "email": "newemail@example.com",
    "current_password": "oldpassword",
    "new_password": "newpassword"
}

    Admin Account Management¶

    Administrators can manage all accounts:

    GET /admin/accounts
Authorization: Bearer <admin-token>

    Events¶

    The account module emits several events that can be hooked into: - account-created - After an account is created - account-pre-update - Before an account is updated - account-updated - After an account is updated - Similar events exist for profile operations

    Testing¶

    The module includes comprehensive test suites for: - Account actions (tests/actions/test_account_actions.py) - Profile actions (tests/actions/test_profile.py) - Account API endpoints (tests/api/) - Profile API endpoints (tests/api/test_profile.py) - Account events (tests/test_account_events.py)
