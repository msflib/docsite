    Account

    Overview¶

    The Account module is a comprehensive system designed to integrate account management and profile services within applications built on MSFLib. It provides various endpoints and configurable options for user account interactions, enhancing both user and admin experiences.

    Features¶

    • Authenticated User Endpoints: /account endpoints for actions like viewing and updating the current user account.
    • Open Registration: Configurable sign-up options that are optional and can be customized per requirements.
    • Admin Management: /admin/accounts endpoints to perform admin-level account creations and modifications.
    • Profile Services: /profiles endpoints for managing user profiles, including uploading avatars.
    • Nested Profile Creation: Option for simultaneous profile creation during account registration.
    • Action Classes: Built-in logic processing with AccountAction and ProfileAction for managing core business functions.

    Installation Guide¶

    This module can be installed using Poetry with git dependencies, and it supports different versions of Pydantic:

    For Pydantic v2 (recommended):

    [tool.poetry.dependencies]
msflib = { git = "https://github.com/msflib/fastapi.git", subdirectory = "core", rev = "dev" }
msflib-account = { git = "https://github.com/msflib/fastapi.git", subdirectory = "modules/account", rev = "dev" }

    Getting Started¶

    Here's a basic setup for including the Account module routers into your application:

    from fastapi import FastAPI
from msflib.account.router import account_router, account_admin_router, profile_router

app = FastAPI()

# User account and profile management
app.include_router(
    account_router(
        get_session=get_session,
        get_current_account=get_current_account,
        settings=settings,
        account_type=Account,
        profile_type=Profile,
    )
)

# Admin account management
app.include_router(
    account_admin_router(
        get_session=get_session,
        role_check=role_check,
        settings=settings,
        account_type=Account,
        profile_type=Profile,
    )
)

# Profile services
app.include_router(
    profile_router(
        get_session=get_session,
        get_current_account=get_current_account,
        get_current_active_account=get_current_active_account,
        settings=settings,
        account_type=Account,
        profile_type=Profile,
    )
)

    API Endpoints Overview¶

    Account Endpoints (/account)¶

    • GET /me: Retrieve current authenticated account details.
    • POST /open: Open registration endpoint, customizable path for sign-ups (when enabled).
    • PUT /me: Update details of the current account.
    • POST /verify-availability: Check availability for email, username, or phone.

    Admin Account Endpoints (/admin/accounts)¶

    • GET /: List all accounts (admin-only access).
    • POST /: Create a new account (admin-only access).
    • PUT /{account_id}: Update an account by ID (admin-only access).
    • GET /{account_id}: Fetch details for a specific account by ID.

    Profile Endpoints (/profiles)¶

    • GET /: Retrieve profile for the current session's account.
    • GET /{account_id}: Retrieve profiles by specific account ID.
    • POST /: Create or comprehensively update the current profile.
    • PUT /: Update fields within the current profile.
    • PUT /avatar: Upload or change the avatar for the current profile.

    Configuration and Custom Schemas¶

    Schema Augmentation: Customize validation schemas for registration endpoints using account_create_type to enhance or override the default models used for new accounts.

    Here's an example of integrating custom models:

    from myapp.schemas import CustomAccountCreate

app.include_router(
    account_router(
        account_create_type=CustomAccountCreate,
        ...
    )
)

app.include_router(
    account_admin_router(
        account_create_type=CustomAccountCreate,
        ...
    )
)

    Events and Testing¶

    Events: This module emits certain events which can be subscribed to, supporting actions like 'account-created' or 'profile-updated'.

    Testing: Execute tests suitable for this module by running:

    ./scripts/test.sh modules/account/msflib/account/tests

    Settings and State Management¶

    Configuration for account behavior, including registration options and initial superuser setup, are managed within a settings scope specific to ACCOUNT.

    By utilizing this module, applications can efficiently administer both user-facing and administrative account tasks with flexibility and ease of customization.
