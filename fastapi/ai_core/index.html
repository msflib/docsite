    MSFLib AI Core Module¶

    msflib-ai-core provides the infrastructure layer for AI features in MSFLib. It contains provider-agnostic factories for chat models, embeddings, vector stores, and request-level usage/rate-limit helpers.

    Overview¶

    This module intentionally has no API router and no domain actions. It is designed to be a foundational layer for AI capabilities in MSFLib-based applications.

    Capabilities¶

    • Unified LLM factory (get_llm) across OpenAI, Anthropic, Azure, Ollama, Bedrock
    • Unified embeddings factory (get_embeddings)
    • Vector store backend dispatch (get_vector_store) for pgvector and future backends
    • Token usage callback for LangChain runs
    • Redis-based request-per-minute limiter
    • LangGraph checkpointer factory with tenant/workspace checkpoint scoping policy and managed context lifecycle
    • LangGraph long-term memory store factory with tenant/workspace namespace policy and managed context lifecycle
    • Dependency namespace helpers for easy FastAPI integration

    Developer Guide Coverage¶

    This documentation is a practical integration guide for downstream applications. It covers:

    1. Runtime policy mapping from resolved settings (LangChainConfigBridge)
    2. Prompt name mapping and context source ordering
    3. Provider-first chunking and ingestion pipeline usage (IngestionPipeline)
    4. Scoped checkpoint utilities (CheckpointScope) and checkpointer factory
    5. Scoped long-term memory utilities (MemoryStoreScope) and store factory
    6. Memory lifecycle event hooks via eventbus (emit_if_listeners)
    7. Retrieval scoping helpers with mandatory tenant/workspace filters (similarity_search_scoped)

    If you are integrating ai_core into a consuming app, start with the examples in:

    1. Downstream Usage Examples
    2. Usage

    Dependency Notes¶

    • langgraph is a direct dependency for checkpoint and long-term memory store integration in ai_core.
    • Postgres checkpointing is optional and enabled by the Poetry extra checkpoint-postgres (langgraph-checkpoint-postgres).
    • Postgres long-term memory store uses the same optional package, langgraph-checkpoint-postgres, enabled via the checkpoint-postgres extra.

    LangGraph Managed Factories¶

    create_langgraph_checkpointer(...) and create_langgraph_store(...) return managed context managers by design.

    • Sync usage: with ... as resource
    • Async usage: async with ... as resource when async_mode=True

    Postgres setup behavior:

    • run_setup defaults to False for both factories.
    • This avoids running database setup DDL on every context entry (for example, once per request in FastAPI).
    • Run setup once during app startup by passing run_setup=True in startup initialization code, then keep request-path usage at the default False.

    Example (sync):

    from msflib.ai_core.services.checkpoint_policy import create_langgraph_checkpointer
from msflib.ai_core.services.memory_store_policy import create_langgraph_store

with create_langgraph_checkpointer(backend="memory") as checkpointer:
    # pass checkpointer into LangGraph compile(...)
    ...

with create_langgraph_store(backend="memory") as store:
    store.put(("tenant", "t1", "workspace", "w1", "memories", "semantic"), "k", {"v": 1})

    Example (async):

    from msflib.ai_core.services.checkpoint_policy import create_langgraph_checkpointer
from msflib.ai_core.services.memory_store_policy import create_langgraph_store

async with create_langgraph_checkpointer(backend="postgres", connection_string=dsn, async_mode=True) as checkpointer:
    ...

async with create_langgraph_store(backend="postgres", connection_string=dsn, async_mode=True) as store:
    ...

    Startup initialization example (postgres):

    from msflib.ai_core.services.checkpoint_policy import create_langgraph_checkpointer
from msflib.ai_core.services.memory_store_policy import create_langgraph_store


def initialize_langgraph_postgres_resources(dsn: str) -> None:
    with create_langgraph_checkpointer(
        backend="postgres",
        connection_string=dsn,
        run_setup=True,
    ) as checkpointer:
        # No need to do anything, the context manager runs the setup.
        pass

    with create_langgraph_store(
        backend="postgres",
        connection_string=dsn,
        run_setup=True,
    ) as store:
        # No need to do anything, the context manager runs the setup.
        pass

    Key Components¶

    Configuration (ai_core/config.py)¶

    Defines the AICoreSettings class which includes: - LLM provider and model configuration - Embedding provider and model configuration - Vector store backend configuration - Rate limiting and token budget settings - Middleware and chunking policies

    Policy Models (ai_core/policy.py)¶

    Defines the policy schemas: - MiddlewarePolicySchema - for middleware activation and configuration - ChunkingPolicySchema - for provider-first chunking strategy

    Dependency Helpers (ai_core/deps.py)¶

    Provides dependency functions for FastAPI integration: - Getting LLM, embeddings, vector store instances - Access to policy bridges and scoped factories

    Services¶

    • checkpoint_policy.py - LangGraph checkpointer factory with scoping
    • chunking/ - Provider-first chunking implementations
    • config_bridge.py - Bridges resolved settings to LangChain-compatible format
    • ingestion_pipeline.py - Pipeline for ingesting documents into vector stores
    • memory_store_policy.py - LangGraph long-term memory store factory with scoping
    • prompt_registry.py - Registry for managing prompts
    • utils.py - Utility functions for AI operations

    Actions (ai_core/actions/)¶

    • prompt.py - Actions for prompt management

    Models (ai_core/models/)¶

    • prompt.py - Data models for prompts

    Providers (ai_core/providers/)¶

    • Provider-specific implementations for LLMs and embeddings

    Vector Store (ai_core/vector_store/)¶

    • Factory and backends for vector stores (currently pgvector)

    Usage Examples¶

    Getting an LLM Instance¶

    from msflib.ai_core.deps import get_llm

# In a FastAPI dependency or service
llm = get_llm()

    Getting an Embeddings Instance¶

    from msflib.ai_core.deps import get_embeddings

embeddings = get_embeddings()

    Getting a Vector Store Instance¶

    from msflib.ai_core.deps import get_vector_store

vector_store = get_vector_store()

    Using the Ingestion Pipeline¶

    from msflib.ai_core.services.ingestion_pipeline import IngestionPipeline
from msflib.ai_core.deps import get_embeddings, get_vector_store

pipeline = IngestionPipeline(
    embeddings=get_embeddings(),
    vector_store=get_vector_store(),
)

# Ingest documents
pipeline.ingest(documents)

    Scoped Checkpointer¶

    from msflib.ai_core.services.checkpoint_policy import create_langgraph_checkpointer
from msflib.ai_core.deps import get_checkpoint_scope

# Get the scope from dependencies (e.g., from a request)
scope = get_checkpoint_scope(tenant_id="t1", workspace_id="w1")

with create_langgraph_checkpointer(scope=scope) as checkpointer:
    # Use checkpointer in LangGraph
    ...

    Scoped Memory Store¶

    from msflib.ai_core.services.memory_store_policy import create_langgraph_store
from msflib.ai_core.deps import get_memory_store_scope

scope = get_memory_store_scope(tenant_id="t1", workspace_id="w1")

with create_langgraph_store(scope=scope) as store:
    # Use store for long-term memory
    store.put(("memories", "semantic"), "key", {"data": "value"})

    Configuration¶

    AI Core settings are accessed via settings.scope("AI_CORE") and include:

    LLM Settings¶

    • LLM_PROVIDER - One of: openai, anthropic, azure, ollama, bedrock, openrouter, groq
    • LLM_MODEL - Model identifier (e.g., "gpt-4o")
    • LLM_API_KEY - API key for the provider
    • LLM_BASE_URL - Custom base URL (for Azure, Ollama, etc.)
    • LLM_TEMPERATURE - Sampling temperature (0.0 to 2.0)
    • LLM_MAX_TOKENS - Maximum tokens to generate

    Embedding Settings¶

    • EMBEDDING_PROVIDER - One of: openai, azure, ollama, bedrock
    • EMBEDDING_MODEL - Embedding model identifier
    • EMBEDDING_API_KEY - API key for the provider
    • EMBEDDING_BASE_URL - Custom base URL

    Vector Store Settings¶

    • VECTOR_STORE_BACKEND - Currently only pgvector
    • VECTOR_STORE_URL - Connection string for PostgreSQL
    • VECTOR_STORE_API_KEY - API key (if required by the backend)
    • VECTOR_STORE_COLLECTION_PREFIX - Prefix for collection names

    Rate Limiting and Budgets¶

    • RATE_LIMIT_RPM - Requests per minute limit
    • TOKEN_BUDGET_PER_WORKSPACE - Maximum tokens per workspace (optional)

    Policies¶

    • MIDDLEWARE_POLICY - Configuration for AI middleware (see MiddlewarePolicySchema)
    • CHUNKING_POLICY - Configuration for chunking strategies (see ChunkingPolicySchema)

    Event Hooks¶

    The AI Core module emits events via the eventbus for memory lifecycle events: - checkpoint-create - When a checkpoint is created - checkpoint-save - When a checkpoint is saved - memory-store-put - When an item is stored in long-term memory - memory-store-get - When an item is retrieved from long-term memory

    Testing¶

    The module includes comprehensive test suites for: - Configuration (tests/test_config.py) - Checkpoint policy (tests/test_checkpoint_policy.py) - Memory store policy (tests/test_memory_store_policy.py) - Config bridge (tests/test_config_bridge.py) - Chunking (tests/test_chunking.py) - Ingestion pipeline (tests/test_ingestion_pipeline.py) - Augmentation architecture (tests/test_augmentation_architecture.py) - Scope utilities (tests/test_scope_utils.py)
