    msflib.authz¶

    Public modules of the msflib-authz package.

    msflib.authz.actions ¶

    Actions for roles, role permissions and role assignments.

    These are plain data access; validation, duplicate checks and events live in services.roles.RoleService, so write through it. A row written here that breaks the service's rules is ignored by resolution (is_effective_assignment).

    Actions take the *Create schemas, which hold no owner, scope or actor: a caller supplies those through update=, which is a visible way around the service's rules.

    msflib.authz.deps ¶

    FastAPI dependency wiring for authz: the require_permission and require_role guards.

    get_authz_dependencies(*, session_dep: Any, tenancy_settings: TenancySettings, get_current_account: Any | None = None, get_current_workspace: Any | None = None, get_current_active_user: Any | None = None, get_current_tenant: Any | None = None, role_service: RoleService | None = None) -> DependencyNamespace ¶

    Return a DependencyNamespace exposing require_permission and require_role.

    The identity callables are those of msflib.scope.get_scope_dependencies. With get_current_tenant the guard uses the request's tenant; without it the default tenant from tenancy_settings is used. A workspace belonging to a different tenant is denied. Platform and tenant guards never resolve a workspace, but need get_current_account.

    msflib.authz.permission_registry ¶

    Code-level registry of permission keys.

    Modules register their own keys at import time::

    from msflib.authz import PERMISSION_REGISTRY
PERMISSION_REGISTRY.register("drivelink.share", tenant_cascade=False)

    tenant_cascade=True lets a tenant-tier assignment satisfy the key inside that tenant's workspaces. Which keys a role bundles is data (RolePermission).

    PermissionRegistry() ¶

    Registered permission keys and their tenant-cascade eligibility.

    register(key: str, *, tenant_cascade: bool = False, tiers: Iterable[RoleTier] | None = None) -> None ¶

    Register a key; idempotent unless tenant_cascade or tiers differ (ValueError).

    key_covers(bundled_key: str, requested_key: str) -> bool ¶

    Does a role bundling bundled_key satisfy requested_key?

    An exact match, or a prefix.* key covering every key under the prefix.

    msflib.authz.seed ¶

    Idempotent seeding of system roles and legacy role/membership backfills.

    Backfills take plain tuples so this module does not import account or workspace models; the consuming app supplies the rows. Each function is one unit of work: it commits once, at the end, through the RoleService method that does the writing.

    seed_system_roles(session: Session, *, default_tenant_id: int, service: RoleService | None = None) -> SeededRoles ¶

    Get or create the seeded system roles; safe to run on every startup.

    A custom role that already holds a seeded identity (same key, tier and owner) raises RoleExistsError (a ValueError) before anything is committed, instead of being treated as the system role.

    seed_role_permissions(session: Session, *, roles: SeededRoles, service: RoleService | None = None) -> list[RolePermission] ¶

    Bundle the currently registered permission keys into the seeded roles.

    • every seeded role: each key its tier may hold (authz.manage_roles is not bundled into workspace roles, nor is a prefix.* key covering it).
    • other roles: none.

    Call after all modules have registered their keys; safe to repeat.

    backfill_account_role_assignments(session: Session, *, roles: SeededRoles, default_tenant_id: int, accounts: Iterable[tuple[int, str]], service: RoleService | None = None) -> list[RoleAssignment] ¶

    Mirror each (account_id, AccountRole value) as a role assignment.

    Transitional: it goes away once assignments replace Account.role.

    accounts must be the complete set: root is platform-tier; admin and user are tenant-tier at default_tenant_id. legacy_backfill assignments the set no longer implies, including those of accounts absent from it, are revoked.

    backfill_workspace_membership_role_assignments(session: Session, *, roles: SeededRoles, memberships: Iterable[tuple[int, int, int, str]], service: RoleService | None = None) -> list[RoleAssignment] ¶

    Mirror each (account_id, workspace_id, tenant_id, UserType value) membership as a workspace-tier assignment.

    Transitional: it goes away once assignments replace User.type.

    memberships must be the complete set: legacy_backfill assignments it no longer implies, including those of removed memberships, are revoked.

    grant(session: Session, *, data: RoleAssignmentCreate, scope: RoleAssignmentScope = UNSCOPED, granted_by_account_id: int | None = None) -> RoleAssignment ¶

    Assign a role (always a runtime grant).

    Granting over an expired runtime assignment renews it and keeps its grantor unless granted_by_account_id is given; an unexpired one raises :class:AssignmentExistsError. A mirrored legacy assignment of the same role is a separate row and is left alone.

    ensure_assignment(session: Session, *, data: RoleAssignmentCreate, scope: RoleAssignmentScope = UNSCOPED, granted_by_account_id: int | None = None) -> RoleAssignment ¶

    Safe to repeat and under races. An existing assignment is returned unchanged; invalid data still raises.

    sync_legacy_assignments(session: Session, *, desired: Sequence[LegacyAssignment], workspace_level: bool) -> list[RoleAssignment] ¶

    Mirror legacy role values as legacy_backfill assignments, in one unit of work.

    Transitional: it goes away once assignments replace the legacy attributes. desired must be the complete set; an empty one does nothing, so a snapshot that failed to load never revokes every mirror. For each entry, the account's legacy_backfill assignments at its scopes other than the wanted one are revoked and the wanted one is ensured. Then every legacy_backfill assignment at the same level (workspace or not) that desired no longer implies, including those of accounts missing from it, is revoked. Runtime grants are separate rows and are never touched.

    has_permission(session: Session, *, account_id: int, tenant_id: int, workspace_id: int | None = None, permission_key: str, platform_only: bool = False) -> bool ¶

    platform_only counts only platform-tier roles.

    Does an assignment of a tier role at (tenant, workspace) apply?

    • platform: always.
    • tenant: same tenant, and the request is tenant-level or the permission is registered tenant_cascade.
    • workspace: exact (tenant_id, workspace_id) only.

    roles ¶

    Role management and permission resolution.

    Resolution is exact-tier matching with a per-permission tenant cascade. RoleService also owns validated writes (roles, role permissions, assignments) and the events they emit. Every public write method is one closed unit of work: its steps run in savepoints, it commits once at the end, and its events fire on that commit. Methods that write several rows (ensure_roles, bundle_permissions, sync_legacy_assignments) commit once for the whole batch. The private _... steps do not commit; only methods in this package compose them.

    LegacyAssignment(account_id: int, scopes: frozenset[tuple[int | None, int | None]], role_id: int | None, tenant_id: int | None = None, workspace_id: int | None = None) dataclass ¶

    What one account's legacy role value implies.

    scopes are the (tenant_id, workspace_id) pairs whose legacy_backfill assignments this entry owns; role_id is None when the value implies no role.

    atomic(session: Session) -> Iterator[None] ¶

    Run a block in a savepoint: it is rolled back as a unit if it raises.

    row_snapshot(row: Any) -> SimpleNamespace ¶

    row's column values, readable after a commit expires or detaches the instance.

    Events fire after the commit and may be handled later or on another thread, so they carry a snapshot taken before it, not the live ORM row.

    commit_unit(session: Session, *rows: Any) -> None ¶

    Commit the unit of work, then reload rows so callers can return them.

    A service method calls this once, after all of its writes. The rows are reloaded with one query per table, not one per row, so a batch stays cheap. Every row must be persistent in session (a transient one raises ValueError); a model with a composite primary key is refreshed row by row.

    msflib.authz.validation ¶

    Shape validation for Role/RoleAssignment tier and scope combinations.

    validate_role_owner_for_tier(*, tier: RoleTier, tenant_id: int | None, workspace_id: int | None) -> None ¶

    A role's owner must fit its tier (mirrors ck_role_tier_scope).

    platform: no owner. tenant: tenant or shared, never a workspace owner. workspace: shared, tenant-owned, or tenant and workspace; never a workspace without a tenant.

    validate_tier_scope_shape(*, tier: RoleTier, tenant_id: int | None, workspace_id: int | None) -> None ¶

    An assignment must name a scope matching its role's tier.

    platform: both None; tenant: tenant_id only; workspace: both set.

    has_valid_tier_scope_shape(*, tier: RoleTier, tenant_id: int | None, workspace_id: int | None) -> bool ¶

    Non-raising :func:validate_tier_scope_shape, for resolution.

    Resolution ignores an assignment whose scope does not match its role's tier, so a badly persisted row never grants authority.

    validate_assignment_within_role_owning_scope(*, role_tenant_id: int | None, role_workspace_id: int | None, assignment_tenant_id: int | None, assignment_workspace_id: int | None) -> None ¶

    A tenant- or workspace-owned role may only be assigned inside its owner scope.

    is_expired(expires_at: datetime | None, now: datetime) -> bool ¶

    NULL never expires. SQLite returns naive datetimes; they are stored as UTC.

    is_effective_assignment(*, tier: RoleTier, role_tenant_id: int | None, role_workspace_id: int | None, assignment_tenant_id: int | None, assignment_workspace_id: int | None, expires_at: datetime | None, now: datetime) -> bool ¶

    Can this assignment grant authority? The single rule every resolution path uses.

    It must name a scope matching its role's tier, stay inside the role's owning scope (what RoleService.grant enforces on write), and not have expired. A row that breaks a rule, however it was written, grants nothing.
