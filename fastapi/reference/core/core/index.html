    Part of the msflib core package.

    msflib.core ¶

    config ¶

    ModuleSettingsBase ¶

    Bases: BaseModel

    Base class for module settings.

    Module settings classes should declare a namespace that matches the key used by SettingsBase.scope() (e.g. CORE).

    flat_aliases maps simple, non-namespaced env var keys (e.g. ENABLE_SSO_AUTH) to the nested settings path (e.g. AUTH.ENABLE_SSO_AUTH). Use it whenever a deployment prefers flat env var names — whether for a new site with a simpler naming convention or when migrating from pre-namespace configurations. Nested keys (e.g. AUTH__ENABLE_SSO_AUTH) take precedence over flat aliases when both are set. Subclasses can override this mapping to provide their own aliases.

    A host AppSettings can also override a module default at code level by declaring a root field with the same bare name (e.g. ENABLE_SSO_AUTH: bool = True on the host class). scope("AUTH").ENABLE_SSO_AUTH will then return the root field's value. This is intentional: the root field acts as a permanent code-level override of the module default.

    request_override_allowlist (optional) is a set of configuration keys that are allowed to be overridden in per-request contexts via ScopedConfigService. If not set (None), all keys are allowed. Set it to a non-empty set to constrain which keys can be mutated via untrusted request paths (e.g., to prevent setting secrets or critical config). The service validates overrides against this allowlist before applying them.

    unwrap() -> ModuleSettingsBase ¶

    Return the underlying module settings instance.

    get_policy_field_schema(field_name: str) -> Any classmethod ¶

    Resolve the schema for one policy field.

    Module author contract: 1. Define policy field on settings class (for example CHUNKING_POLICY). 2. Prefer annotating the field with a policy model class. 3. If annotation is a plain mapping, define the policy model in sibling policy.py and follow naming convention from _policy_schema_candidate_names.

    Resolution order: 1. Field annotation if it is a BaseModel subclass 2. Sibling policy.py auto-discovery

    resolve_tiered(*, tenant_config: Mapping[str, Any] | None = None, user_config: Mapping[str, Any] | None = None, request_override: Mapping[str, Any] | None = None) -> ModuleSettingsBase ¶

    Resolve runtime overrides on top of current validated settings.

    Returns a new validated instance of the same settings type.

    tenant_config may carry workspace-scoped values pre-merged by the caller — workspace overrides are folded into the tenant layer before this method is invoked rather than being exposed as a separate parameter.

    SettingsBase(**data: Any) ¶

    Bases: BaseSettings

    Base application settings.

    Module settings composition uses two approaches:

    Option A: Direct Mixin Inheritance relies on multiple inheritance and field overrides, which is simpler but may be susceptible to name clashes and uses normal Pydantic validation and .env support.

    class Settings(ModuleASettings, ModuleBSettings, SettingsBase):
    ...
    OVERRIDDEN_SETTING_1 = "overridden_value"   # from module A
    OVERRIDDEN_SETTING_2 = "overridden_value"   # from module B
    ...

    Option B: Composed Settings with Nested Modules relies on nested settings objects (e.g. AUTH) and also uses normal Pydantic validation and .env support.

    class Settings(SettingsBase):
    MODULE_A: ModuleASettings = ModuleASettings(
        OVERRIDDEN_SETTING_1="overridden_value",
        ...
    )
    MODULE_B: ModuleBSettings = ModuleBSettings(
        OVERRIDDEN_SETTING_2="overridden_value",
        ...
    )

    Consumer projects can override specific values by passing settings to the composed settings class (or by subclassing and overriding defaults).

    normalize_request_override(request_override: Mapping[str, Any] | None) -> dict[str, Any] ¶

    Normalize request override from envelope or direct mapping.

    Handles both formats: - Direct mapping: {"KEY": value, ...} - Envelope: {"overrides": {"KEY": value, ...}}

    Returns a flat dict of overrides.

    validate_request_override_allowlist(module_settings: ModuleSettingsBase, request_override: dict[str, Any], collect_errors: bool = False) -> list[tuple[Any, str]] | None ¶

    Validate request override keys against module allowlist.

    If the module defines request_override_allowlist, ensure all override keys are in that set. Otherwise, all keys are allowed. If collect_errors is True, returns a list of (key, reason) tuples for rejected keys. Otherwise, raises ValueError listing all unsupported string keys and rejects non-string keys with ValueError.

    get_scoped_or_flat_env(namespace: str, key: str) -> str | None ¶

    Return a scoped env var first, then legacy flat env var.

    Example: namespace="WORKSPACES", key="ENABLE_X" tries WORKSPACES__ENABLE_X then ENABLE_X.

    get_module_setting(setting_name: str, namespace: str, module_setting: ModuleSettingsBase) -> Any ¶

    Resolve a module setting from env overrides, falling back to defaults.

    Resolution order: 1. {NAMESPACE}__{SETTING_NAME} 2. {SETTING_NAME} (legacy flat env var) 3. getattr(module_setting, setting_name)

    merge_config_layers(*, base_config: Mapping[str, Any] | None = None, tenant_config: Mapping[str, Any] | None = None, workspace_config: Mapping[str, Any] | None = None, user_config: Mapping[str, Any] | None = None, request_override: Mapping[str, Any] | None = None) -> dict[str, Any] ¶

    Merge runtime overrides using deterministic precedence.

    The merge applies layers in this order: tenant -> workspace -> user -> request override

    Base defaults and environment overrides are expected to come from SettingsBase / ModuleSettingsBase instantiation.

    Note: callers may still pre-fold workspace values into tenant values. If provided separately, workspace_config takes precedence over tenant_config and lower precedence than user_config.

    compose_settings_model(name: str, base_settings_type: type[SettingsBase], module_settings: Iterable[type[ModuleSettingsBase]] = ()) -> type[SettingsBase] ¶

    Create a composed Settings class from module settings classes.

    Each module settings class becomes a field on the composed settings, with its corresponding class instance used as the default.

    If multiple definitions share the same namespace, later entries override earlier defaults.

    errors ¶

    Shared error classification for ingestion-style background workers.

    Generic -- no module-specific logic -- so any module's worker (documents, knowledge's extraction worker, ingestion's pipeline-stage wrapper, etc.) can reuse the same terminal-vs-retryable classification instead of each maintaining its own copy. Lives here rather than in any one consumer module so it can be shared without creating a dependency between them (e.g. msflib.ingestion deliberately doesn't depend on msflib.documents).

    import_tools ¶

    is_importable(*module_names: str) -> bool cached ¶

    True if every named module can be imported (cached for this process).

    A cheap availability probe for optional-dependency gating (is_available()-style checks). Returns False only when the named module itself (or a parent package of it) is missing. Other failures — a genuine bug in an installed module (e.g. a SyntaxError), or an ImportError from one of its dependencies rather than the module being probed — still propagate, since misreporting those as "not installed" would hide the real failure instead of surfacing it.

    Pass multiple names when a feature needs more than one optional module present.

    optional_install_hint(*, pip_package: str, extra: str, distribution: str) -> str ¶

    Poetry-flavored install instructions for a missing optional package.

    import_optional(module_name: str, *, feature: str, pip_package: str, extra: str, distribution: str) -> ModuleType ¶

    Import an optional module, raising a Poetry install hint on failure.

    Use this instead of a bare importlib.import_module call at any site where a missing optional dependency should fail with actionable guidance rather than a bare ModuleNotFoundError. For availability probes (is_available()-style checks), use :func:is_importable instead.

    distribution is the Poetry package that declares extra (e.g. "msflib-ai-core", "msflib-documents") — the caller's own package, not necessarily this one.

    readiness ¶

    Readiness: which deployment requirements are met, and which are not.

    Checks answer "is this requirement met?" and never change anything. Remedies are the safe, idempotent fixes for checks. Each msflib module may ship <module>.readiness with a registry; :meth:Suite.from_settings collects the registries of the modules an application composes, adds core's own, and the application adds its own::

    from msflib.core.readiness import Suite

suite = Suite.from_settings(settings, engine=engine, migration=MIGRATION,
                            unmanaged_tables=["langchain_pg_*"])

# python -m msflib.core.readiness --suite app.readiness:suite --profile prod --fix

    capture ¶

    Capture library logging and Python warnings while checks run.

    Libraries such as Alembic log dozens of INFO lines and warn through logging and warnings. Printed as they happen they bury the report; captured, the warnings become findings attached to the check that caused them and the rest is dropped (or kept with --verbose).

    Attribution follows the thread, not "whichever check is running now". A check runs on its own thread (so it can time out) and that thread carries a :class:_Token naming the check. Threads it starts inherit the token, so everything a check causes belongs to it, even when its thread outlives the timeout and the next check has already started. Whatever no check thread emitted is kept separately as unattributed.

    The hooks that make this work are process-global (the root logging handlers, warnings and Thread.start), so one capture runs at a time. A thread that outlives its timeout is abandoned: its output is dropped, and the hooks stay in place until no abandoned thread is alive.

    drift ¶

    Classify what inspect_database reports as drift.

    Alembic's compare_metadata lists every difference between the database and the models. They are not equal. A missing table or column means the schema is behind; a table the models do not declare (LangChain's PGVector tables, an extension's catalog) means nothing at all, so the two are reported separately.

    migration_risk ¶

    A static look at pending Alembic revisions for operations that can lose data.

    --fix may only apply a migration without a human when nothing in it can destroy data. A revision script is arbitrary Python, so this is a conservative scan of the revision file (not its downgrade()), not a proof: it flags what it recognises and anything it cannot read. A flagged revision is never applied automatically; the operator reviews it and runs the migration.

    find_destructive_operations(script_location: str | Path, revisions: Iterable[str]) -> list[str] ¶

    reject_if_not_public_ip(address: str, *, hostname: str) -> None ¶

    Raise ValueError if address isn't a public, routable IP.

    Shared SSRF-guarding primitive: any caller resolving a hostname before connecting to it (fetching a URL, validating a downstream-configured dictionary/data source, ...) should reject private/internal addresses rather than connecting to whatever a hostname happens to resolve to. See resolve_public_ips/validate_public_http_url below for the usual entry points -- this is the primitive they share.

    resolve_public_ips(hostname: str) -> list[str] ¶

    Resolve hostname and reject it if any address is non-public.

    Guards against SSRF (fetching cloud metadata endpoints, internal services, loopback, etc.) via a caller-supplied hostname. A caller that opens the actual connection itself (rather than handing a URL to a library that does its own DNS resolution) should call this again at connect time, on the same lookup that opens the socket, rather than trusting an earlier, separate lookup -- otherwise a malicious DNS server can answer a public IP for an earlier check and a private one for the actual connection (DNS-rebinding TOCTOU). See msflib.ai_core.tools.fetch_url's connect-time transport for that pattern; validate_public_http_url below does only the early check.

    validate_public_http_url(url: str) -> str ¶

    Validate url is http(s) with a hostname resolving to a public address.

    Returns url unchanged, for convenient call-site chaining (e.g. url = validate_public_http_url(url) across a redirect chain). This is the early, one-shot check -- it doesn't itself close the DNS-rebinding TOCTOU window described on resolve_public_ips; a caller that opens the connection itself should re-validate at connect time instead of relying on this alone.
