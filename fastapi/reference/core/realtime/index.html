    msflib.realtime¶

    Part of the msflib core package.

    msflib.realtime ¶

    Realtime: push what happens in the backend to connected clients, over SSE or WebSocket.

    Emit with hub.emit(channel, event, data); clients listen to channels ("workspace:7", "conversation:conv_01...") through the streams in router.router. See hub.py for the delivery guarantees and auth.py for how streams are authenticated.

    auth ¶

    Who may listen to what.

    Browsers cannot send an Authorization header from EventSource or WebSocket, so a stream can be opened in two ways, and a host app can offer either or both:

    • Bearer header -- for fetch-based SSE clients and non-browser clients. bearer_authenticator turns the app's existing access-token check into an authenticator.
    • Ticket -- the client first asks for a short-lived signed ticket over a normal authenticated request (POST <prefix>/tickets), then opens the stream with ?ticket=.... The ticket names the channels it was granted, so they are checked once, when it is issued.

    Authorization is a separate question from authentication: Authorizer(principal, channel) says whether this principal may read this channel (e.g. "is a member of the workspace"). Authorization is evaluated when a stream or subscription starts; it is not re-evaluated while the stream is open, so a membership that ends mid-stream takes effect on the next (re)connect.

    StreamIdentity(id: str, channels: frozenset[str] | None = None, claims: Mapping[str, Any] = dict()) dataclass ¶

    The authenticated party behind a stream connection.

    TicketSigner(secret: str, ttl_seconds: int = 60, algorithm: str = 'HS256') ¶

    Issues and verifies short-lived, signed one-time credentials called tickets.

    A ticket is a JWT the server mints for an already-authenticated client so the client can open an SSE or WebSocket stream without sending its bearer token as a header. (Browser EventSource and WebSocket APIs cannot set Authorization; a ticket is passed as a query parameter instead.) Tickets are stateless — they can be reused until they expire — so keep ttl_seconds short (the client should use the ticket immediately) and transmit them only over TLS.

    authenticate(authenticators: Iterable[Authenticator], conn: HTTPConnection) -> StreamIdentity | None async ¶

    The first identity any of the authenticators recognises.

    route_authorizers(routes: Mapping[str, Authorizer]) -> Authorizer ¶

    Send each channel to the authorizer of its prefix ({"conversation:": ..., "workspace:": ...}); the longest matching prefix wins and a channel nobody claims is denied.

    bearer_authenticator(token_resolver: Callable[[str], StreamIdentity | Awaitable[StreamIdentity | None] | None]) -> Authenticator ¶

    Authenticate Authorization: Bearer <token> with the app's own token check.

    ticket_authenticator(signer: TicketSigner, param: str = 'ticket') -> Authenticator ¶

    Authenticate ?ticket=<ticket>. A missing or invalid ticket is simply not recognised.

    hub ¶

    The hub: emit from anywhere in the backend, stream for one client.

    Guarantees, for either backend:

    • Broadcast. Every client subscribed to a channel receives every event, not one of them.
    • Order. Events arrive in the order they were emitted.
    • Ids. Each event of a channel has an id that increases with every emit. A client that reconnects sends the last id it saw and receives exactly what it missed, nothing older and nothing twice.
    • Bounded. Only the most recent history events per channel are kept. A client that was away longer than that is told with a resync event, and should reload its data.
    • No connection, no cost. A client without a last id only sees what is emitted after it subscribed.

    router ¶

    A ready-made router: SSE stream, WebSocket and ticket endpoints.

    ::

    hub = build_hub(RealtimeSettings(redis_host=..., redis_port=...))
app.include_router(
    router(
        hub=hub,
        authenticators=[bearer_authenticator(resolve_access_token)],
        authorizer=may_read_channel,
        signer=TicketSigner(settings.SECRET_KEY),   # optional: enables tickets
    ),
    prefix="/api/v1/realtime",
)

    Endpoints: GET /stream?channel= (SSE), WS /ws, POST /tickets (only with a signer).

    router(*, hub: RealtimeHub, authenticators: Sequence[Authenticator], authorizer: Authorizer, signer: TicketSigner | None = None, settings: RealtimeSettings | None = None) -> APIRouter ¶

    authenticators identify callers by their normal credentials (bearer header...). With a signer, streams can also be opened with a ticket obtained from POST /tickets.

    testing ¶

    Helpers for tests of apps that use the realtime module.

    reset_sse_starlette_loop() -> None ¶

    sse-starlette keeps a class-level shutdown Event that stays bound to the first event loop it sees, while Starlette's TestClient uses a new loop for every request ("bound to a different event loop"). A server has one loop for its lifetime, so this only matters in tests: call it before each request, or from an autouse fixture.

    read_sse_events(client: Any, url: str, *, params: dict | None = None, headers: dict | None = None, timeout: float = 5.0) -> list[dict] ¶

    The events a stream replays, as dicts with id, event and the parsed data.

    Adds replay_only=true so the stream ends after the retained backlog (a TestClient cannot read an endless stream); skips keep-alive comments and the initial retry frame.

    transports ¶

    sse ¶

    Server-Sent Events transport: one channel per stream, resumable with Last-Event-ID.

    sse_response(hub: RealtimeHub, channel: str, *, last_event_id: str | None = None, replay_only: bool = False, retry_ms: int = 3000, ping_seconds: int = 15) -> EventSourceResponse ¶

    A response streaming channel's events.

    replay_only ends the stream after the retained backlog instead of waiting for new events. Production streams are endless; it exists for tests, because Starlette's TestClient cannot consume an infinite response.

    websocket ¶

    WebSocket transport: one connection, any number of channels.

    Protocol (JSON text frames).

    Client -> server::

    {"type": "subscribe", "channel": "workspace:7", "last_event_id": "41"}   # id optional
{"type": "unsubscribe", "channel": "workspace:7"}
{"type": "ping"}

    Server -> client::

    {"type": "subscribed", "channel": "workspace:7", "last_event_id": "41"}
{"type": "event", "channel": "workspace:7", "id": "42", "event": "message-posted", "data": {}}
{"type": "unsubscribed", "channel": "workspace:7"}
{"type": "error", "channel": "workspace:7", "code": "forbidden", "message": "..."}
{"type": "pong"}

    subscribed.last_event_id is the position the subscription starts from. A client that reconnects subscribes again with the id of the last event it received on that channel and gets what it missed -- or a resync event ("event": "resync") when that is no longer possible, exactly as over SSE. A connection that is not authenticated is closed with code 4401.
