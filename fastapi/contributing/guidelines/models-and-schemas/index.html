    Models and schemas¶

    MDL-1 · Use the msflib base classes¶

    Tables extend ModelBase (id, timestamps, lifecycle events). Every new schema extends SchemaBase, never pydantic's bare BaseModel, including request fragments and response contracts with no table behind them. Enums extend BaseEnum.

    Known gap

    Some existing schemas predate this rule and still extend BaseModel: documents/schema.py, ingestion/schema.py, ai_api/schema.py, ai_api/contracts.py, ai_core/policy.py and drivelink/models/validation.py. Don't migrate them as a side effect of other work (STY-6); new schemas in those modules still follow this rule.

    MDL-2 · Schemas live next to their table¶

    models/<entity>.py holds the table and its Create/Update/Read schemas, which are the ModelAction generic parameters. A request class that doesn't match one table's CRUD shape (a composite request, or a narrow slice of a shared Update) still lives in the file of the entity it is about. Don't add a cross-entity schema.py; when reworking a module that has one, delete it once nothing in it lacks a model-file home. Existing schema.py files (see the MDL-1 note) are not moved as a side effect of other work.

    Shared column groups go in SchemaBase mixins (AccountFieldsMixin, KnowledgeScopeMixin).

    MDL-3 · Create/Update hold only caller-supplied fields¶

    Anything the server derives — principal, path-resolved ids, tenant/workspace scope, computed defaults, timestamps, counters — stays off the schema, even as an optional field. Pass it through action.create(..., update={...}) or action.update(..., update={...}) at the call site.

    Why: a field that every caller overwrites still appears in the OpenAPI contract and invites clients to rely on it. Update schemas shared by several operations (rename, archive, change visibility) don't need narrowing to one caller's fields.

    MDL-4 · Don't add a DTO that restates Create/Update¶

    Use the model's Create/Update as the request body, or subclass it to add one or two genuinely request-only fields. Reference: conversation/models/resource_link.py::ResourceLinkCreate, used directly by the router.

    MDL-5 · One Read per entity, and only when something uses it¶

    A single XxxRead per entity serves both internal code and the HTTP response. Build responses with XxxRead.model_validate(row).model_copy(update={...}), overriding only derived fields such as a related row's public_id. Don't define Read classes speculatively; an unused Read is dead code.

    MDL-6 · Scope columns¶

    • Always-scoped rows: tenant_id: int = Field(foreign_key="tenant.id", index=True), not null, no default. Add msflib-tenancy as a dependency.
    • Sometimes-scoped rows: tenant_id: int | None = Field(default=None, foreign_key="tenant.id", index=True); null means not tenant-scoped.
    • workspace_id: int | None, where None is a valid bucket (SCP-2).
    • Import the tenant model as msflib.tenancy.models.tenant.Tenant.

    MDL-7 · Don't denormalise scope columns without a query that needs them¶

    If a child table's queries really need scope columns, denormalise every dimension they filter on, never tenant alone. Otherwise the parent foreign key is the single source of truth, and the few queries that need scope join to the parent. Symmetric precedent: KnowledgeScopeMixin.

    MDL-8 · Use portable column types¶

    Use sqlalchemy.JSON, not JSONB, unless a Postgres-only feature is required; tests run on SQLite.

    MDL-9 · Relationship() fields¶

    • Allowed within the module and to a declared hard dependency (ARC-5).
    • A file with a Relationship() must not use from __future__ import annotations. Use quoted forward references: thread: Optional["ConversationThread"] = Relationship(). Import the related class under TYPE_CHECKING if needed to break a cycle.
    • Add many-to-one sides only. Don't add collection sides on hot tables (Conversation.messages); paginate through the action instead.

    Why: see Known pitfalls.

    MDL-10 · Format enums directly¶

    BaseEnum renders its plain value through str() and f-strings, whether the attribute holds a live enum member or a plain string after a flush. Write f"{row.kind}". Don't add .value or hasattr(x, "value") guards in new code. Compare a field against members of its own enum type, not another enum that happens to share values.
