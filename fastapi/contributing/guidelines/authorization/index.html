    Authorization¶

    Rules for code that grants, checks or guards access, written from the review of msflib-authz (#306). They apply to modules/authz, to the guards in modules/auth, and to any module that protects an endpoint. The module's own page (msflib-authz, added with #306) has the tables and examples; these rules say what to preserve when changing it.

    AUZ-1 · Keep tier, owner and scope apart¶

    A role has three separate facts, and each lives in a different column (see Three questions about a role):

    Fact Question Stored on
    tier what level of authority does it grant? Role.tier
    owner who defined it, and who may use it? Role.tenant_id, Role.workspace_id
    scope where does this one grant apply? RoleAssignment.tenant_id, RoleAssignment.workspace_id

    NULL means "shared, no owner" on a role and "no tenant or workspace here" on an assignment. Never compare a role_* id with an assignment_* or request id as if they were the same thing; the names in the code (role_tenant_id, assignment_tenant_id) say which is which. Don't rename the columns to hide the distinction; document it.

    AUZ-2 · One rule decides whether an assignment can grant authority¶

    (The combinations are tabulated under Valid and invalid combinations.)

    is_effective_assignment (tier shape, the role's owner scope, expiry) is the only definition. Every read path (has_permission, get_role_keys_for) reaches it through one internal step. Do not add a resolution query that loads assignments another way, or a second copy of the rule.

    Why: every round of review found another read path that skipped one of the three checks.

    AUZ-3 · Compare roles by tier-qualified key¶

    Use RoleKey(tier, key). A bare key cannot tell the seeded tenant admin from the workspace admin. The authz guards (require_role) take RoleKey only, and a legacy admin mirrored by a backfill is a tenant-tier role that never satisfies a platform RoleKey.

    AUZ-4 · Authority comes from the tier, never from NULL ids¶

    A platform role is platform-wide because its tier says so. NULL scope ids on an assignment of a tenant or workspace role are invalid and grant nothing. Enforce shape in the service on write, ignore bad rows on read (EDG-7), and add database CHECKs for everything a single table can express.

    AUZ-5 · Two ways to guard a route; authz does not leak into auth¶

    msflib-auth guards (RoleCheck, WorkspaceRoleCheck) compare a role attribute and are supported as the simple way. msflib-authz guards read assignments: require_permission(key, tier=...) for an action, require_role(RoleKey(tier, key)) for a role. Pick one way per route. auth must not import authz, and authz must not import auth; identity arrives as injected callables.

    Name permission keys <module>.<action>, register them at import time, and choose tenant_cascade deliberately: True lets a tenant-tier role grant the permission inside any workspace of its tenant. require_role takes RoleKey only; a bare string is a TypeError.

    AUZ-6 · Write through RoleService; actions skip validation¶

    Actions are plain data access. A row created through one is checked by nobody, so do it only in tests that need an invalid row. Actions take the client schemas only, so scope and actor reach a row only through an explicit update=. In application code use create_role, ensure_role, grant, ensure_assignment and revoke.

    AUZ-7 · Authz services commit their own unit of work¶

    Every public authz service method is one closed unit of work (SVC-4): its writes run in savepoints, it commits once at the end, and its events fire on that commit. A method that writes several rows commits once for the whole batch (RoleService.ensure_roles, bundle_permissions, sync_legacy_assignments; GroupService.delete_group).

    • A method that other methods compose is split into a private step (_grant, _revoke) that does not commit and a public method that calls the step and commits. Only methods inside the authz package call the private steps.
    • The documented composition parameters are commit=True on AccessService.grant, AccessService.revoke_resources, ResourceSharing.share and ResourceSharing.revoke_all. The drivelink create-with-initial-shares and delete flows pass commit=False, so the node and its grants land in one commit and a failing step leaves neither. The role and group services have no such parameter.
    • Anything else that needs authz writes joined to its own goes through the same shape: a named caller, a documented parameter, a test that a failure leaves nothing behind.

    AUZ-8 · Deny by default¶

    Deny on a missing tenant when a tenant dependency is wired, an unknown tier, an unregistered permission key, a workspace of another tenant, and an expired assignment. Defaults (the default tenant) apply only when no dependency is configured.

    AUZ-9 · Legacy support is transitional¶

    (See Legacy roles.)

    The authz guards ignore Account.role and User.type. The two backfills mirror them into legacy_backfill assignments so a route can move from auth to authz without losing access, and they exist until assignments replace the attributes. Do not extend them. The two sources are independent: revoking an assignment does not change the attribute. Backfills take the complete set and revoke what it no longer implies; a partial list revokes too much.

    AUZ-10 · Rule changes update the docs tables¶

    The valid and invalid combinations table on the authz module page is checked against the code. Change a rule, change the table, and add the case to both the write test (grant rejects it) and the read test (a raw row that breaks it grants nothing).

    AUZ-11 · Scope and actor are parameters, not fields of *Create¶

    RoleCreate and RoleAssignmentCreate hold only what a client may send. The owner, scope, grantor and system flag are decided by the server and go to the service as owner=RoleOwner(...), scope=RoleAssignmentScope(...), granted_by_account_id and created_by_account_id (MDL-11). Build them in the endpoint from the request context, never from the body. A test asserts that the client schemas declare none of those fields.
